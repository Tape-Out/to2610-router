# to2610-router 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

四口 100 Mbps 的 IPv4 路由芯片，面向 ECOS 2610 班车。片上没有处理器，转发全由硬件做：收完一帧、查过头部、查路由表、改写两个 MAC 地址与 TTL，从另一个口发出去。四个口各接一个网段，与 `to2610-switch` 成对使用：每个网段一台交换机，交换机的一个口接到路由器上。

各口的地址与路由表由片外主机经 SPI 写进去。复位后路由器是关着的，表是空的；主机配完并打开，它才开始转发。

它由息壤从组织的 IP 库装配而成，没有一行自有 RTL：`erouter` 是路由核心（四口、16 条路由、每口三块 128 字节的帧缓冲），`spis` 是 SPI 从口，片外主机经它读写片上总线，`gpio` 给出六根通用管脚，其中两根拨 MDIO 管 PHY。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 端口 | 4 个 RMII 口 | 每口接一颗片外 RMII PHY，片上不含 PHY；每口有自己的 MAC 地址与 IPv4 地址，由主机写入 |
| 速率与双工 | 100 Mbps 全双工 | RMII 每拍收发 2 位，参考时钟 50 MHz。不支持 10 Mbps 与半双工 |
| 转发方式 | 存储转发 | 整帧收进缓冲、FCS 对了才判去向。转出的帧由发送端重算 FCS |
| 帧长 | 最长 128 字节（不含 FCS） | 即 IP 包最长 114 字节，接在它上面的主机要把 MTU 设成 114。更长的帧整帧丢掉并计数 |
| 链路层过滤 | 目的 MAC 是本口地址、类型是 0x0800 | 发给别的地址的、广播的 IPv4、别的类型（IPv6 等）都丢掉并计数 |
| 头部检查 | RFC 1812 5.2.2 的五项，加头部不超出帧 | IP 部分不少于 20 字节、校验和对、版本为 4、头长不少于 20 字节、总长不小于头长；不能关 |
| TTL | 减一 | 到达时为 0 或 1 的包丢掉并计数（RFC 1812 5.3.1），不回 ICMP 超时 |
| 校验和 | 增量更新 | 照 RFC 1624 式 3，只改 TTL 所在的那个字；带选项的头部原样转 |
| 路由表 | 16 条，最长前缀匹配 | 每条是前缀、前缀长、出口、下一跳的 MAC；等长时槽号小的赢（RFC 1812 5.2.4.3）；0.0.0.0/0 即默认路由 |
| 下一跳 | 表项里写着的 MAC | 转出时目的 MAC 换成它，源 MAC 换成出口的地址。路由器自己不发 ARP |
| ARP | 只应答 | 问本口 IPv4 地址的请求就地答（RFC 826），主机因此能解析出网关的 MAC；问别的地址不答 |
| 缓冲 | 每个入口三帧 | 前一帧在发、后面的照收，同一口背靠背来的帧不丢；三块都压着没发完的包时再来的整帧丢掉并计数。同一入口的帧按原来的次序发出 |
| 出口仲裁 | 轮转 | 几个入口同时要一个出口，各自的帧存在各自的缓冲里，轮流发出，不丢 |
| 计数 | 十个 32 位计数器 | 收到的帧、转发的包、答过的 ARP，以及七种原因各丢了多少 |
| 管理口 | SPI 从口，模式 0 | SCK 不超过主频的八分之一，即 6.25 MHz；可读写片上任意地址 |
| 通用管脚 | 6 根，逐根设方向 | 0、1 两根拨 MDC、MDIO 管理 PHY，其余 4 根空余 |
| 复位默认 | 关着 | 总开关为 0，地址与路由表全空；关着时不收帧、不答 ARP、不计数 |

### 转发过程

每个口收到的字节连同 FCS 存进本口的缓冲，前 42 字节另存一份供判决，IP 头部的校验和边收边算。帧尾到了，按下面的次序判，命中一条就定下去向：

1. 帧开头时本口三块缓冲都压着没发完的包：丢，记 `busycnt`
2. FCS 不对或 PHY 报了接收错：丢，记 `fcscnt`
3. 比缓冲长：丢，记 `longcnt`
4. 是问本口 IPv4 地址的 ARP 请求：就在缓冲里改写成应答，从原口发回，记 `arpcnt`
5. 目的 MAC 不是本口地址，或类型不是 0x0800：丢，记 `l2cnt`
6. 头部检查不过：丢，记 `hdrcnt`
7. TTL 为 0 或 1：丢，记 `ttlcnt`
8. 路由表里没有匹配的前缀，或匹配到的出口不存在：丢，记 `routecnt`
9. 否则挂到出口上。出口从入口的缓冲里逐字节取出，边发边改写：目的 MAC、源 MAC、TTL、校验和，其余原样；发完记 `fwdcnt`，入口腾空

一帧从收完到开始发只隔几拍，延迟主要是收一整帧的时间：100 Mbps 下每字节 80 纳秒，98 字节的 ping 帧约 8 微秒。

### 管理口协议

SPI 模式 0（CPOL 0、CPHA 0），高位先出，`CS_N` 低有效。地址与数据都是 4 字节大端，地址低 2 位不看。与 `to2610-switch` 是同一个 `spis`，协议相同。

| 命令 | 主机发 | 芯片回 |
|:--:|:--:|:--:|
| 0x02 写 | 4 字节地址，再每字 4 字节数据 | 无；每收满一字写一次，地址加 4 |
| 0x03 读一字 | 4 字节地址，1 个空字节 | 4 字节数据 |
| 0x0B 连读 n + 1 字 | 4 字节地址，1 字节 n，1 个空字节 | 每字 4 字节 |
| 0x05 状态 | 1 字节 | 第 0 位：总线回了错；第 1 位：主机快过总线。读一次即清 |
| 0x9F 标识 | 4 字节 | 53 50 49 53，即「SPIS」 |

### 主机端工具

`sw/spis.py` 是上面的协议，`sw/router.py` 是寄存器地址与常用操作，经 USB 转 SPI（FT232H）或树莓派的 spidev 连芯片。整片测试与联合仿真也经这两个文件管芯片，所以上板用的就是测过的那份。

| 命令 | 做什么 |
|:--:|:--:|
| load 文件 | 整份配置写进去并打开：先关，写各口的 MAC 与 IP、写路由表，没写到的清零，再开 |
| ident | 读管理口标识 |
| on、off | 总开关 |
| port 口号 MAC IP | 改一个口的地址 |
| route 槽号 前缀/长度 出口 MAC | 改一条路由。开着时也能改：先撤有效位，写完再置上 |
| drop 槽号 | 撤一条路由 |
| ports、routes、counters | 读回各口地址、有效的路由、十个计数器 |
| mdio 物理地址 寄存器 [值] | 经 GPIO 读或写一颗 PHY 的寄存器 |

配置文件是 TOML，`sw/net.toml` 是两个网段的例子（也是联合仿真用的那一份）：

```toml
[[port]]                      # 按次序是 0 号口、1 号口……
mac = "02:00:00:00:01:00"
ip = "10.0.0.1"               # 这个网段的主机把它设成网关

[[route]]
to = "10.0.1.10/32"           # 直连的主机也要各写一条
port = 1
via = "02:00:00:00:00:12"     # 那台主机网卡的 MAC
```

路由器不发 ARP，下一跳的 MAC 只能由人写进表里。所以每台要跨网段通信的主机占一条 /32；通往别的路由器的网段则一条前缀就够，`via` 写那台路由器的 MAC。16 条用完为止。

## 寄存器

地址、位宽与复位值由报告按 `erouter` 与 `gpio` 的 `regmap.yaml` 和本仓 `ip.yaml` 的基地址生成，这里只写含义。MAC 与 IP 都是先上线的字节在最高位。

| 寄存器 | 含义 |
|:--:|:--:|
| ctrl | en 为总开关，为 0 时不收帧、不发帧 |
| machi、maclo | 第 p 口 MAC 地址的高 16 位与低 32 位 |
| ipaddr | 第 p 口的 IPv4 地址，问它的 ARP 请求由本口应答；写 0 则本口不答 |
| rprefix | 第 i 条路由的目的前缀 |
| rcfg | 第 15 位为有效，第 11 至 8 位为出口，第 5 至 0 位为前缀长（0 至 32） |
| rnhhi、rnhlo | 第 i 条路由下一跳 MAC 的高 16 位与低 32 位 |
| rxcnt | 收到的帧，丢掉的也算 |
| fwdcnt | 转发出去的包，不含 ARP 应答 |
| fcscnt | 因 FCS 不对或接收错丢掉的 |
| l2cnt | 因目的 MAC 不是本口、或不是 IPv4 丢掉的（含没应答的 ARP） |
| hdrcnt | 因头部检查不过丢掉的 |
| ttlcnt | 因 TTL 用尽丢掉的 |
| routecnt | 因没有路由丢掉的 |
| longcnt | 因比缓冲长丢掉的 |
| busycnt | 因本口三块缓冲都压着包丢掉的 |
| arpcnt | 应答过的 ARP 请求 |
| dout | 每根管脚的输出值 |
| din | 每根管脚当前的输入电平 |
| dir | 每根一位，1 为驱出，0 为输入 |

## 板级连接

| payload 位 | 信号 | 接到 |
|:--:|:--:|:--:|
| 7p 至 7p+2 | 口 p 的 TXD[1:0]、TX_EN | PHY p 的 RMII 发送脚 |
| 7p+3 至 7p+6 | 口 p 的 RXD[1:0]、CRS_DV、RX_ER | PHY p 的 RMII 接收脚 |
| 28 至 55 | 没用到 | 高阻，悬空即可 |
| 56、57、58 | SCK、CS_N、MOSI | 管理主机，SPI 模式 0 |
| 59 | MISO | 管理主机；只在 CS_N 为低时驱动 |
| 60、61 | GPIO 0、1 | 各 PHY 的 MDC、MDIO，由主机端脚本经 GPIO 拨出 |
| 62 至 65 | GPIO 2 至 5 | 空余：PHY 复位、指示灯、拨码 |

p 取 0 至 3，所以 0 号口占第 0 至 6 位，3 号口占第 21 至 27 位，每口七位的排法与 `to2610-switch` 相同；管理口与 GPIO 也在与它相同的位上（56 至 65），两颗芯片共用一种管理排线，板子可以照同一份原理图画。payload 第 n 位是 MPC-Frame 的 `user_io[n + 7]`；逐位的完整位表在报告的「payload 位表」里。

- 时钟 50 MHz，必须与四颗 PHY 的 RMII `REF_CLK` 同源：一颗晶振经扇出缓冲同时给芯片与各 PHY，PHY 设成参考时钟输入。
- PHY：任意 RMII 100 Mbps PHY（LAN8720A、RTL8201F 等），每口一颗，配带网络变压器的 8P8C 插座；100BASE-TX 只用插座的 1、2、3、6 四根线。对端只支持 10 Mbps 或半双工时不能用；要限定，经 MDIO 把 PHY 的 4 号寄存器改成只通告 100 Mbps 全双工并重启自协商。
- MDIO：四颗 PHY 共用一条 MDIO，地址拨码要互不相同，MDIO 线要上拉。
- 复位：按住复位时全部 payload 脚高阻。每口的 TX_EN 在板上留一颗 10 kΩ 下拉，PHY 才不会在这段时间把悬空的脚当成在发送。
- 管理口必须接：USB 转 SPI（FT232H）或树莓派接第 56 至 59 位，SCK 不超过 6.25 MHz。配置存在触发器里，掉电或复位就没了，上电后要重新 `load`。也可以接 `to2610-kvc` 的 SPI1 主口，由那颗芯片上的 Linux 来配（`spimode dev` 之后用 `spix` 重放录好的收发）。
- 与 `to2610-switch` 互联：路由器的一个口与交换机的任意一个口各接一颗 PHY，两个插座之间一根网线。两颗芯片在同一块板上、同一个 50 MHz 时，也可以不要 PHY，RMII 口对口直连：一头的 TXD、TX_EN 接另一头的 RXD、CRS_DV，RX_ER 接地；联合仿真就是这样接的。
- 主机：网关设成所在网段那个口的地址，MTU 设成 114（Linux 上是 `ip link set dev eth0 mtu 114`）。

## 测试说明

整片测试：四台主机各接一个口、各占一个网段，网关是路由器的那个口。

| 用例 | 验证什么 |
|:--:|:--:|
| closed_until_configured | 复位后不配置：不答 ARP、不转发、不计数；配好打开就 ping 通 |
| management | 读标识；各口地址与路由表写进去再读回；访问没有东西的地址回错并记在状态字里；整份重写时没写到的口与表项清零 |
| arp_gateway | 问本口地址的 ARP 请求得到应答，逐字节核对；问别的地址、问别的口的地址都不答 |
| ping_across | 跨网段 ping 通：主机先解析网关的 MAC，包到对面时 TTL 是 63，应答原路回来；转发与应答的计数对得上，没有丢帧 |
| ping_pairs | 两对主机同时跨网段互 ping，再换一种配对 |
| route_table | 没有路由时丢并计数；加默认路由后走它；更长的前缀压过默认路由；直连主机的 /32 压过两者；撤掉一条又回到默认路由。表在路由器开着时改 |
| drops | TTL 为 1 与 0、头部校验和错、别的口的 MAC、广播的 IPv4、不是 IPv4、FCS 错、没有路由，八帧各记在各自的计数器上，一帧也不转出；之后照常转发 |
| frame_sizes | 正好 128 字节的帧转出去，与独立算出的结果逐字节相同；129 字节的整帧丢掉并计数 |
| back_to_back | 同一个口上背靠背三帧、出口空着时三帧都按序转出，一帧不丢；两个口各背靠背十帧同时发往同一个出口，出口发不过来，三块都压着包时再来的丢掉并记在 `busycnt` 上（判真丢了），送到的与丢掉的加起来是二十帧，送到的逐字节对、同一入口的不乱序。门级冒烟也跑这一项 |
| switch_off | 运行中关掉就不转发，再打开照常 |
| mdio | 经 GPIO 拨出 MDIO：读 PHY 的标识寄存器，写一个寄存器并在 PHY 模型里核对 |
| gpio | 余下的四根 GPIO 当输出时驱到焊盘上，当输入时读得回外面给的电平 |

联合仿真（`htest/test_net.py`）：两颗 `to2610-switch` 中间夹这一颗，三颗都是交付的那份 `.v`，交换机的 7 号口分别接路由器的 0、1 号口；每台交换机上两台主机，两个网段是 10.0.0.0/24 与 10.0.1.0/24。交换机不碰管理口，路由器写进 `sw/net.toml`。

| 用例 | 验证什么 |
|:--:|:--:|
| across | 两个网段的主机互 ping 通，两个方向各一对；包到达时 TTL 是 63；路由器转发 4 个包、答 4 次 ARP |
| local_stays_local | 同一网段的两台经交换机直接通，TTL 还是 64；路由器一个包也不转 |
| both_ways_at_once | 两个方向同时 ping |
| closed_router | 路由器没配置时跨网段不通，网段内照通 |
| no_route | 发往没有路由的网段：网关答了 ARP，包到路由器被丢并计数 |

真流量（`htest/tcp.sh`）：同一套联合仿真，A0、B0 的位置换成宿主机上两个网络命名空间里的 TAP 网卡，两头是真的 TCP/IP，宿主机来的帧按线速连发；B0 上的 HTTP 服务是 FastAPI，只听 TAP 的地址，测试一个包也不出托管机。跨网段 ping 三次都回，A0 经 HTTP 从 B0 取 64 KiB、md5 相同。同一测试量过每口一到三块缓冲：

| 每口缓冲 | 取 64 KiB 用时 | 发送方重传 | 路由器因口上压着包丢的帧 |
|:--:|:--:|:--:|:--:|
| 一块 | 1182 秒 | 500 段 | 551 / 2706（20%） |
| 两块 | 485 秒 | 28 段 | 13 / 2165（0.6%） |
| 三块 | 485 秒 | 19 段 | 1 / 2164（0.05%） |

用时是仿真的墙钟时间，只拿来比几种缓冲；一块时一半以上的数据段要重传，两块还剩同一入口长短帧交替时的丢帧，这一颗用三块。

全部用例跑在交付的那份 `.v` 上，经五口顶层进出；管理走 `sw/` 里上板用的同一份代码。`erouter` 自己的测试台另查头部检查的每一项、前缀边界、校验和为 0 的特例等，逐项与独立算出的结果比。

## 局限

- 路由器自己不发 ARP，下一跳的 MAC 要人写进路由表：直连的主机每台占一条 /32，16 条用完为止。配置不掉电保存，上电后要主机重新写。
- 每个入口三块缓冲：前一帧在发、后面的照收，同一口背靠背来的帧不丢；几个入口同时长时间满速发往同一个出口时，出口发不过来，三块都压着包时再来的帧丢掉并计数，TCP 靠重传恢复。
- 帧最长 128 字节：缓冲是触发器搭的，MPC-Frame 不许硬宏，四口各放一个 1518 字节的缓冲比整颗芯片还大；512 字节一块时 11.9 万单元、1 mm² 里布不通；128 字节一块时 6.1 万单元、布线干净；现在每口三块 128 字节，综合 8.5 万单元，利用率取 0.3。主机要把 MTU 设成 114，ping（默认 84 字节的 IP 包）与 ARP 不受影响，大包靠 TCP 按 MTU 切。
- 不回任何 ICMP（超时、不可达），所以对它 `traceroute` 看不到这一跳，路径 MTU 发现也不起作用；路由器自己的地址只答 ARP，ping 它不通。
- 不分片、不处理 IP 选项（带选项的包原样转）、不转发广播与组播、没有 IPv6、不认 802.1Q 标签。
- 只有 100 Mbps 全双工；链路状态不读 PHY。
